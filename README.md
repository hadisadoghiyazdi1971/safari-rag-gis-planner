# Safari RAG+GIS Itinerary Planner

Reference implementation accompanying the paper *"A Dynamic Multi-Modal
Knowledge Fusion Framework for Personalized Travel Itinerary Optimization"*
(submitted to *Engineering Applications of Artificial Intelligence*).

The system builds a multimodal knowledge base of African wildlife
photographs (CLIP embeddings + BLIP captions + LLM-enriched descriptions,
filtered to verified African locations), formulates personalized safari
destination selection as a 0–1 knapsack binary integer program (PuLP/CBC),
and converts the selected destinations into a routed (OSRM), narrated (LLM)
itinerary with an interactive map.

## Repository structure

```
src/
  embeddings/   Feature extraction: CLIP image embeddings + BLIP captions
                (image_processor.py, model_manager.py)
  rag/          Knowledge base construction: geographic filtering, keyword
                retrieval, persistent LLM caption enrichment
                (enhanced_africa_rag_with_llm_smart.py, llm_enhancer.py,
                description_manager.py, africa_geo_filter.py)
  optimization/ Destination selection (PuLP/CBC BIP), OSRM routing, LLM
                narrative generation, interactive map output
                (safari_multi_route_planner.py, interactive_safari_storyteller.py)
data/           Curated destination attributes, precomputed description
                database/export, and example case-study outputs
results/        Precomputed CLIP embeddings + BLIP captions for the
                geographically filtered image collection
outputs/        Example interactive map generated by the optimization module
legacy/         Earlier/exploratory scripts superseded by the files in src/;
                kept for provenance, not part of the described pipeline
```

## What each part of the pipeline actually does

This README intentionally matches the "Limitations and Future Work" section
of the paper rather than describing an idealized system, so that the code
and the manuscript stay consistent.

- **Feature extraction and geographic filtering** (`src/embeddings`,
  `src/rag`) are fully implemented and were used to produce the dataset
  statistics reported in the paper: 3,000 raw images processed, 910 (30.3%)
  retained after geographic filtering, 87 (9.6%) with LLM-enriched captions
  at the time of the reported experiments.
- **Retrieval** over the resulting knowledge base is currently keyword-based
  (substring matching over captions/tags/descriptions) combined with the
  geographic validity flag. The CLIP embeddings are computed and stored
  (`results/image_embeddings.npz`) but are **not yet used for
  similarity-based ranking**; `legacy/vector_store.py` contains an
  unfinished FAISS-based similarity search module that is not wired into
  the rest of the pipeline and is not compatible with the current data
  schema as-is.
- **User constraint collection** is a single-pass structured interaction
  (starting location, budget, maximum destinations), not a multi-turn
  Bayesian/entropy-driven preference elicitation.
- **Destination selection** (`src/optimization/safari_multi_route_planner.py`)
  solves a genuine 0–1 knapsack BIP with PuLP/CBC for the primary
  ("Maximum Lions") route. The other route variants generated alongside it
  ("Diverse Experience", "Budget Friendly", "Classic Safari") are produced
  by separate deterministic heuristics, not independent BIP solves.
- **Routing** queries the public OSRM demo server
  (`router.project-osrm.org`), which is rate-limited and not intended for
  production traffic.
- `legacy/safari_trip_planner.py` has a known data-modeling issue: its
  `LionSightingOptimizer` treats the trip's starting city as a candidate
  safari destination, which can cause the start city itself to be selected
  as a "sighting" location. It is kept for provenance but should not be
  used as-is.

```bash
pip install -r requirements.txt

```

## Running the pipeline

1. `src/embeddings/model_manager.py` downloads the CLIP/BLIP model weights.
2. `src/embeddings/image_processor.py` extracts CLIP embeddings and BLIP
   captions from raw images into `results/`.
3. `src/rag/enhanced_africa_rag_with_llm_smart.py` applies geographic
   filtering, persistent LLM caption enrichment, and produces the
   description database/export in `data/`.
4. `src/optimization/safari_multi_route_planner.py` solves the BIP model,
   generates the heuristic route variants, queries OSRM, and writes the
   interactive map (see `outputs/`).
5. `src/optimization/interactive_safari_storyteller.py` generates the
   LLM-based day-by-day narrative for a selected itinerary.

## Data notes

- `data/African.xls` and the wildlife photographs referenced by it were
  collected from the 500px platform and are subject to that platform's
  terms of use; this repository redistributes only the derived CLIP/BLIP
  features and filtered text descriptions, not the original images.
- The per-destination cost and wildlife-sighting attributes used in the
  optimization case studies (paper Table 5) were curated from publicly
  reported seasonal guidance, not fitted to observed booking prices or
  verified sighting statistics.
